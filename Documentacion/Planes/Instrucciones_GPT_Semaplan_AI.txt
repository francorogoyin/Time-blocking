Instrucciones base para configurar Semaplan en ChatGPT.

Modo recomendado para GPT Actions.

Usar un Custom GPT con GPT Actions y API key por header. Esta es la
superficie adecuada para que ChatGPT pueda leer y operar tareas,
hábitos, Planes, Archivero, Baúl y Decoteca.

La App MCP queda como B1 de lectura. Puede seguir usándose para
consultas, pero no es la superficie recomendada para la B2 de
escritura.

Nombre sugerido.

Semaplan.

Texto exacto sugerido para pegar en el campo `Instructions` del GPT.

`Documentacion/Planes/Prompt_GPT_Semaplan_AI.txt`.

Base URL viva actual.

`https://cprdnxkkhuuhdispubds.supabase.co/functions/v1/semaplan-ai`.

Contrato OpenAPI para GPT Actions.

Usar este contrato vivo:

`https://cprdnxkkhuuhdispubds.supabase.co/functions/v1/semaplan-ai/openapi-key.json`.

El contrato declara exactamente 30 operaciones para respetar el límite
de ChatGPT Actions. No usar `openapi.json` ni
`Documentacion/Planes/OpenAPI_Semaplan_AI.yaml`, porque conservan el
modo OAuth y rutas internas que no corresponden al GPT.

Autenticación recomendada.

Usar API Key con header personalizado. No usar OAuth, Bearer, client
ID ni client secret.

Valores.

- Authentication: `API Key`.
- Auth type: `Custom header`.
- Header name: `X-Semaplan-AI-Token`.
- API key: valor local de `SEMAPLAN_AI_CHATGPT_API_TOKEN`.

Flujo final para el GPT.

1. En ChatGPT, crear o editar el Custom GPT `Semaplan`.
2. Pegar el contenido de `Prompt_GPT_Semaplan_AI.txt` en
   `Instructions`.
3. En `Knowledge`, adjuntar
   `Documentacion/Planes/Conocimiento_GPT_Semaplan_AI.txt`.
4. En `Actions`, importar la URL del contrato vivo.
5. Configurar la API key con el header de arriba.
6. Guardar y probar una lectura de tareas antes de ejecutar una
   mutación.
7. En `Capabilities`, activar `Web Search`. La configuración usa GPT
   Actions y Web Search; no agregar Apps al mismo GPT.

- `semaplan_habitos`.
- `semaplan_slots`.
- `semaplan_plan_semana`.
- `semaplan_planes_periodos`.
- `semaplan_listar_archivero`.
- `semaplan_buscar_archivero`.
- `semaplan_listar_baul`.
- `semaplan_listar_metas`.
- `semaplan_buscar_global`, con `modulo=decoteca`, para obras, tecas,
  metadatos, partes, estadísticas y registros de Decoteca.

Paginación y lotes de Decoteca.

En `semaplan_buscar_global`, cuando `modulo=decoteca`, usar `limite` y
`offset`. El `offset` empieza en 0 y se aplica después de los filtros y
del orden estable de la teca. La respuesta incluye `Total`, `Offset`,
`Limite`, `Hay_Mas` y `Siguiente_Offset`.

Para campos vacíos usar el filtro explícito, no una búsqueda textual. Por
ejemplo, pedir las primeras cinco obras de Biblioteca sin descripción con
`filtros[descripcion_vacia]=true`, `offset=0` y `limite=5`. También están
disponibles `creador_vacio`, `anio_vacio`, `genero_vacio`,
`subgenero_vacio`, `portada_vacia`, `total_unidades_cero`, `estado`,
`periodo` y `prioridad`.

Para reducir el tamaño de la respuesta usar `compacto=true`. Ese modo
conserva la identidad y los campos de catálogo necesarios, pero omite
registros de avance, partes completas, metadatos e imágenes codificadas.
El modo compacto es recomendable para listados por lotes.

Después de editar un lote de obras, volver a consultar con `offset=0` y
el mismo filtro. Las obras ya completadas dejarán de coincidir y la
siguiente tanda ocupará naturalmente los primeros resultados.

Acciones que exigen confirmación explícita.

- Borrar una tarea.
- Aplicar una operación masiva.
- Deshacer una mutación.
- Borrar una obra o una teca de Decoteca.
- Cambios en Discoteca.
- Cambios estructurales de agenda o planes vinculados.
- Administración de tokens.

Lotes operativos.

`semaplan_b2_lote_operaciones` admite hasta 50 acciones en una
mutación atómica. Cada elemento del arreglo `operaciones` combina una
`accion` B2 y su `payload`, por lo que puede operar Tareas, Hábitos,
Planes, Archivero, Baúl y Decoteca en una única previsualización. El GPT debe
resolver los IDs, pedir la previsualización sin `confirmar_aplicacion`
y repetir el mismo payload con `confirmar_aplicacion: true` solo
después de la confirmación.

Las altas claras y correcciones verificadas de una sola obra de
Decoteca también usan el lote, pero con `confirmar_aplicacion: true`.
Para borrar o aplicar dos o más cambios de Decoteca, el GPT debe pedir
primero la previsualización y luego una confirmación humana.

Decoteca y búsqueda web.

`semaplan_b2_lote_operaciones` incorpora estas acciones internas, sin
agregar operaciones OpenAPI nuevas: `crear_obra_decoteca`,
`editar_obra_decoteca`, `borrar_obra_decoteca`,
`crear_teca_decoteca`, `editar_teca_decoteca` y
`borrar_teca_decoteca`.

La consulta se hace con `semaplan_buscar_global`: `q` busca una obra y
devuelve su ficha completa con metadatos, partes, datos de la teca y
registros. Para listar una teca completa, usar `modulo=decoteca` y
`teca_id=Biblioteca`, `Musicoteca`, `Videoteca`, `Ludoteca` o el ID de
una teca personalizada.

Para altas y revisiones bibliográficas, el GPT debe usar Web Search
antes de mutar Semaplan. Debe priorizar fuentes primarias, de autor,
editorial, biblioteca, Open Library o Wikidata; comparar la edición y
guardar URL de procedencia en los metadatos. La carátula se guarda solo
como una URL pública de imagen confiable, nunca como archivo descargado
ni miniatura efímera. La Action no descarga imágenes.

El scope nuevo es `write_decoteca`. Los tokens existentes que ya tienen
`write_metas` conservan compatibilidad para esta primera migración. Al
emitir un token nuevo para una integración con Decoteca, asignar ambos
`read` y `write_decoteca`.

Compatibilidad.

- En ChatGPT Actions, usar API key por `X-Semaplan-AI-Token` y
  `/openapi-key.json`.
- En ChatGPT Apps o MCP remoto, mantener el uso B1 de lectura.

Notas.

- `GET /salud` sirve solo para chequeo técnico.
- `GET /openapi-key.json` es el único contrato vivo para importar en
  ChatGPT Actions.
- La B2 registra mutaciones con idempotencia y auditoría en Supabase.
